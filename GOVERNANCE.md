# Governance

## Maintainer

USS has one maintainer. The maintainer:

- reviews and merges each pull request;
- decides what the standard contains;
- acts as the Community Moderator of the [Code of Conduct](CODE_OF_CONDUCT.md);
- publishes each release.

The owner of the repository, HaleTechCo, names the person who holds this
role. `.github/CODEOWNERS` shows the current holder.

## How decisions are made

1. Anyone may propose a change in an issue or a pull request.
2. People discuss the proposal in public, in the issue or the pull request.
3. The maintainer decides. The maintainer gives the reason when a proposal is
   declined.
4. A decision about a rule follows `standard/conventions.md`. A change to a
   rule that a release already holds follows section 10 of that file.
5. Anyone may ask the maintainer to reconsider. Give new facts or a new
   argument.

## How to become a maintainer

The project has no path yet, because it has one maintainer. HaleTechCo may
appoint more maintainers. This file changes when it does.

## Succession

If the maintainer leaves, HaleTechCo takes one of two steps:

1. It appoints a new maintainer.
2. It archives the repository. It then says so in the README, so that users
   know that nobody maintains USS.
